# 1. GDB가 하는 일

## 디버거

프로그램은 평소 운영체제 위에서 **연속 실행**된다.  
디버거를 붙이면:

1. 특정 지점에서 **실행을 멈출** 수 있고  
2. 그 순간의 **CPU 상태(레지스터)** 와 **메모리** 를 읽을 수 있으며  
3. 값을 바꾼 뒤 **이어서 실행**할 수 있다.

GDB(GNU Debugger)는 Linux·유닉스 계열에서 C/C++·어셈블리 수준 분석에 널리 쓰인다.  
보안 맥락에서는 “버그 수정”뿐 아니라 **취약점이 터지는 순간**을 재현·관찰하는 수단이다.

## 관찰 대상

| 대상 | 의미 |
|------|------|
| 명령 포인터 (RIP/EIP) | 다음에 실행할 명령 주소 |
| 범용 레지스터 | 연산 중간값, 인자, 반환값 후보 |
| 스택 | 지역 변수, 저장된 반환 주소, 버퍼 |
| 힙·데이터 영역 | 동적 할당, 전역·정적 데이터 |
| 소스/어셈 | 현재 어느 줄·어느 명령인지 |

Linux 101에서 본 **프로세스**, **메모리 맵**, **fd** 가 여기와 연결된다.  
GDB는 그 프로세스 안에 “들여다보는 창”을 연다.

## 디버그 정보 (`-g`)

```bash
gcc -g -O0 -o demo demo.c
```

| 옵션 | 역할 |
|------|------|
| `-g` | 심볼·소스 줄 번호 등 디버그 정보 포함 |
| `-O0` | 최적화 끔. 변수·줄 대응이 단순해짐 |

스트립된 바이너리·최적화 빌드도 디버깅 가능하지만, 소스 줄·변수 이름이 없거나 어긋날 수 있다.  
워게임 배포 바이너리는 심볼이 없는 경우가 많다 → **주소·어셈** 중심으로 본다.

## 권한·보안 관련 전제

| 항목 | 비고 |
|------|------|
| ASLR | 매 실행 주소가 달라질 수 있음. `set disable-randomization on/off` |
| PIE | 코드 기반도 이동. `info file`, `break *offset` 등 |
| 권한 | 다른 사용자 프로세스 attach는 제한될 수 있음 |
| 커널 | `ptrace` 관련 설정(Yama 등)이 attach를 막을 수 있음 |

## GDB vs printf 디버깅

| | printf | GDB |
|--|--------|-----|
| 재빌드 | 로그 넣을 때마다 | 불필요(심볼 있으면) |
| 중간 상태 | 찍은 지점만 | 임의 중단·임의 주소 확인 |
| 배포 바이너리 | 소스 수정 불가 | 그대로 분석 가능 |
| 타이밍 | 출력으로 동작 변할 수 있음 | 중단 자체도 타이밍에 영향 있음 |

둘 다 쓰되, **메모리 손상·분기 조건**은 GDB가 유리한 경우가 많다.
