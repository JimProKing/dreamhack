## 리눅스 기본 명령어

웹 셸·SSH·Docker 컨테이너 안에서 자주 씀.  
경로: `.` = 현재, `..` = 상위, `/` = 루트, `~` = 홈.

### 어디에 있나 / 이동

| 명령 | 의미 | 예 |
|------|------|-----|
| `pwd` | 현재 경로 출력 | `pwd` |
| `ls` | 목록 | `ls`, `ls -la` |
| `ls 경로` | 그 경로 목록 | `ls ./dream/hack/hello/` |
| `cd 경로` | 이동 | `cd /tmp`, `cd ..` |
| `cd` / `cd ~` | 홈으로 | |

| `ls` 옵션 | 의미 |
|-----------|------|
| `-l` | 자세히 (권한, 크기, 날짜) |
| `-a` | 숨김 파일(`.` 시작) 포함 |
| `-la` / `-al` | 둘 다 |

### 파일 내용

| 명령 | 의미 | 예 |
|------|------|-----|
| `cat 파일` | 전체 출력 | `cat hint.txt` |
| `head 파일` | **앞** n줄 (기본 10) | `head -n 20 f` |
| `tail 파일` | **뒤** n줄 (기본 10) | `tail -n 20 f`, `tail f` |
| `tail -f 파일` | 파일이 늘어날 때 계속 출력 | 로그 모니터링 |
| `less 파일` | 페이지 단위 (q 종료) | `less big.log` |
| `wc -l 파일` | 줄 수 | |

`cat` 은 처음부터 전부, `head` 는 앞, **`tail` 은 끝** 쪽을 볼 때 씀.  
큰 파일·로그·“맨 아래 힌트” 찾을 때 `tail` 이 유리.

### 셸 글로브 (와일드카드) — 필터 우회에 자주 씀

| 기호 | 의미 | 예 |
|------|------|-----|
| `*` | 아무 문자열 (빈 문자열 포함) | `*.txt`, `hello/*` |
| `?` | 아무 문자 **1개** | `????.txt` → 4글자 이름 |
| `[abc]` | a 또는 b 또는 c | `file[12].txt` |

명령 문자열에 `flag` 가 들어가면 막는 필터가 있을 때:

```bash
# 안 됨
cat ./dream/hack/hello/flag.txt

# 됨 (파일명에 flag 를 직접 안 씀)
cat ./dream/hack/hello/*
cat ./dream/hack/hello/????.txt
```

`*` / `?` 는 **셸이 먼저** 실제 파일 이름으로 펼친 뒤 명령에 넘김.

### 리다이렉트·파이프 (기초)

| 문법 | 의미 |
|------|------|
| `cmd > f` | 출력을 파일로 (덮어쓰기) |
| `cmd >> f` | 이어 쓰기 |
| `cmd < f` | 입력을 파일에서 |
| `cmd1 \| cmd2` | cmd1 출력 → cmd2 입력 |

## 워게임: baby-linux (#837)

- 링크: https://dreamhack.io/wargame/challenges/837

- 정리: `war_game/baby-linux_837/`

### 문제 요지

웹에서 리눅스 명령을 실행하는 서비스.  
`flag.txt` 를 찾아 내용을 출력하면 플래그 (`DH{...}`).

### 필터

소스에 대략:

```python
if 'flag' in cmd:
    return ... 'No!'
```

명령 문자열에 **`flag` 가 포함되면** 실행 거부.

| 안 됨 | 됨 |
|-------|-----|
| `cat flag.txt` | `cat ./dream/hack/hello/*` |
| `cat ./dream/hack/hello/flag.txt` | `cat ./dream/hack/hello/????.txt` |

### 풀이 순서

1. 서버 생성 → 브라우저 접속  
2. `ls` — 파일 목록 (`hint.txt` 등)  
3. `cat hint.txt` — 경로 힌트 `./dream/hack/hello/`  
4. `ls ./dream/hack/hello/` — `flag.txt` 존재 확인  
5. `cat ./dream/hack/hello/*` — 필터 우회 후 내용 출력  
6. `DH{...}` 제출  

### 치트시트

```text
ls
cat hint.txt
ls ./dream/hack/hello/
cat ./dream/hack/hello/*
```

### 터미널 색으로 숨긴 문자열 (`tail` / drag)

파일을 읽었을 때 이런 식의 안내가 나오는 경우:

```text
Changed to terminal color! Only the tail command can read this string correctly!... or drag? :
```

**의미**

- 플래그(또는 비밀 문자열)가 **터미널 색(ANSI 이스케이프)** 으로 칠해져 있음  
  예: 글자색 = 검정, 배경 = 검정 → `cat` 해도 **안 보이거나** 안내 문구만 보임
- 힌트 두 가지:
  1. **`tail`** 로 읽기 — 문제/환경이 `tail` 을 쓰라고 지정한 경우  
  2. **drag** — 마우스로 출력 영역을 **드래그(드래그 선택)** 하면 선택 하이라이트 때문에 숨은 글자가 보임

**시도할 명령 예**

```bash
# 파일 끝 쪽 보기 (힌트가 tail 을 지목할 때)
tail ./dream/hack/hello/*
tail -n 5 파일

# 색 코드까지 보이게 (이스케이프 문자 표시)
cat -v 파일
# 또는
od -c 파일
xxd 파일 | head
```

| 방법 | 설명 |
|------|------|
| `tail 파일` | 끝부분 출력. 문제가 “tail only” 라고 하면 우선 시도 |
| 드래그 선택 | GUI 터미널/웹 출력에서 빈 것처럼 보이는 줄 드래그 → 숨은 글자 노출 |
| `cat -v` / `od` / `xxd` | 눈에 안 보이는 제어문자·색 코드 확인 |
| 배경색 바꾸기 | 검정 글자가 보이게 테마 변경 (환경에 따라) |

**ANSI 색 (개념)**

- 터미널은 `\033[...m` 같은 **이스케이프 시퀀스**로 글자/배경색을 바꿈  
- 예: 검정 글자 `ESC[30m` … `ESC[0m` (리셋)  
- 일반 `cat` 은 색을 “적용”해서 보여 주므로, 배경과 같으면 안 보임  
- 바이트 그대로 보면 (`cat -v`, hexdump) 코드가 보임  

#837 흐름과 합치면:

```text
ls → cat hint.txt → ls 경로 → cat 경로/*  (또는 tail 경로/*)
# 출력이 이상하면: tail 다시 / 드래그 선택 / cat -v
```

## Linux Lab — ELF / ps / kill

랩 환경: Ubuntu 22.04, 프롬프트 `dreamhack@linux-lab:~$`

### 1. `hello world!` 출력 ELF 만들기

파일 이름 **`hello`**, 형식 **ELF**, 실행 시 출력 문자열이 채점 기준과 **완전 일치**해야 함.

```bash
cat > hello.c << 'EOF'
#include <stdio.h>
int main(void) {
    printf("hello world!\n");
    return 0;
}
EOF

gcc -o hello hello.c
chmod +x hello
./hello
file hello
```

| 포인트 | 내용 |
|--------|------|
| 출력 | `hello world!\n` (대소문자·`!`·개행 정확) |
| 이름 | `hello` (`a.out` 아님) |
| 형식 | `file hello` → **ELF** (셸 스크립트 X) |
| `return 0` | C99+ `main` 에서는 생략해도 0. 필수는 아님 |

```bash
./hello | od -c   # 바이트 확인용
```

### 2. `ps` — 프로세스 목록 / 상태 코드

#### `ps aux`

| 옵션 | 의미 |
|------|------|
| `a` | 다른 사용자 프로세스 포함 |
| `u` | 유저 친화 상세 형식 |
| `x` | 터미널 없는 프로세스도 표시 |

```bash
ps aux | grep ps_test
```

예시 출력:

```text
dreamha+ 30471 ... S+ ... grep --color=auto ps_test
```

→ **`ps_test` 가 아님.** 명령줄에 `ps_test` 문자열이 있어 걸린 **grep 자신**.  
STAT `S+` = sleep + 포그라운드.

`grep` 자기 자신 제외:

```bash
ps aux | grep '[p]s_test'
```

#### `ps -el`

| 옵션 | 의미 |
|------|------|
| `-e` | 모든 프로세스 |
| `-l` | long 형식 (S 열 = 상태) |

```bash
ps -el | grep ps_pid_test
```

실습 출력:

```text
1 R  1001    91     1 26  80   0 -   660 -      ?        00:04:41 ps_pid_test
F S   UID   PID  PPID ...                              CMD
```

| 칸 | 값 | 의미 |
|----|-----|------|
| **S** | **`R`** | Process State Code (**Running**) |
| PID | `91` | 프로세스 ID |
| TTY | `?` | 제어 터미널 없음 |
| CMD | `ps_pid_test` | 프로세스 이름 |

문제 “`ps_pid_test` 의 Process State Code” → 답 **`R`**.

| 코드 | 의미 |
|------|------|
| **R** | Running |
| **S** | Interruptible sleep |
| **D** | Uninterruptible sleep |
| **T** | Stopped |
| **Z** | Zombie |

#### 이름으로 보기

```bash
ps -C ps_test -o pid,stat,cmd
ps -C kill_test_proc -o pid,stat,cmd
```

### 3. `kill` — 프로세스 종료

**PID 숫자**만 인자로 받음. 이름 넣으면 에러.

```text
$ kill kill_test_proc
-bash: kill: kill_test_proc: arguments must be process or job IDs
```

올바른 순서:

```bash
ps -el | grep kill_test_proc
# 4 R  1000   174     1 ... kill_test_proc
#              ^^^ PID

kill 174          # SIGTERM (기본, 정상 종료 요청)
# 안 죽으면
kill -9 174       # SIGKILL 강제
```

실습: `kill_test_proc` PID `174` → `kill 174` 로 종료.

| 명령 | 의미 |
|------|------|
| `kill PID` | SIGTERM (15) |
| `kill -9 PID` | SIGKILL 강제 |
| `killall 이름` | 이름으로 종료 |
| `pkill 이름` | 이름 패턴으로 종료 |

### 랩 세션 요약 (실제 입력 흐름)

```bash
ls
# hello  hello.c  kill_test_proc  kill_test_proc.c

# ELF 다시 만들기
rm hello hello.c   # 필요 시
cat > hello.c << 'EOF'
#include <stdio.h>
int main(void) {
    printf("hello world!\n");
    return 0;
}
EOF
gcc -o hello hello.c

# 상태 코드
ps -el | grep ps_pid_test
# → S 열 R  → 답: R

# kill
ps -el | grep kill_test_proc
# → PID 174
kill 174
```

## 오늘 배운 것 (한 줄)

1. `ls` / `cd` / `cat` / `pwd` 로 탐색·읽기
2. `head` = 앞, **`tail` = 뒤**
3. `gcc -o hello hello.c` 로 ELF 생성, 출력 문자열·파일명 정확해야 채점 통과
4. `return 0` 은 `main` 에서 필수는 아님 (C99+)
5. `ps aux` / `ps -el` 로 목록·**STAT/S** 상태 코드 확인
6. `ps ... \| grep foo` 에 뜨는 `grep foo` 줄은 대상 프로세스가 아님
7. `kill` 은 **PID** (`kill 174`), 이름이면 `killall` / `pkill`
8. 문자열 필터(`flag`)는 `*` / `?` 글로브로 우회
9. 터미널 색으로 숨긴 문자열 → `tail` / 드래그 / `cat -v`
