## 리눅스 기본 명령어

웹 셸·SSH·Docker 컨테이너 안에서 자주 씀.  
경로: `.` = 현재, `..` = 상위, `/` = 루트, `~` = 홈.

### 어디에 있나 / 이동

| 명령 | 의미 | 예 |
|------|------|-----|
| `pwd` | 현재 경로 출력 | `pwd` |
| `ls` | 목록 | `ls`, `ls -la` |
| `ls 경로` | 그 경로 목록 | `ls ./dream/hack/hello/` |
| `cd 경로` | 이동 | `cd /tmp`, `cd ..` |
| `cd` / `cd ~` | 홈으로 | |

| `ls` 옵션 | 의미 |
|-----------|------|
| `-l` | 자세히 (권한, 크기, 날짜) |
| `-a` | 숨김 파일(`.` 시작) 포함 |
| `-la` / `-al` | 둘 다 |

### 파일 내용

| 명령 | 의미 | 예 |
|------|------|-----|
| `cat 파일` | 전체 출력 | `cat hint.txt` |
| `head 파일` | **앞** n줄 (기본 10) | `head -n 20 f` |
| `tail 파일` | **뒤** n줄 (기본 10) | `tail -n 20 f`, `tail f` |
| `tail -f 파일` | 파일이 늘어날 때 계속 출력 | 로그 모니터링 |
| `less 파일` | 페이지 단위 (q 종료) | `less big.log` |
| `wc -l 파일` | 줄 수 | |

`cat` 은 처음부터 전부, `head` 는 앞, **`tail` 은 끝** 쪽을 볼 때 씀.  
큰 파일·로그·“맨 아래 힌트” 찾을 때 `tail` 이 유리.

### 찾기 / 검색

| 명령 | 의미 | 예 |
|------|------|-----|
| `find 경로 -name '이름'` | 파일 찾기 | `find . -name '*.txt'` |
| `grep 패턴 파일` | 내용 검색 | `grep DH flag.txt` |
| `which 명령` | 실행 파일 위치 | `which cat` |

| `mkdir 디렉터리` | 폴더 생성 | `mkdir work` |
| `mkdir -p a/b/c` | 중간 경로까지 생성 | |

| `cp -r 폴더 대상` | 폴더 복사 | |

### 셸 글로브 (와일드카드) — 필터 우회에 자주 씀

| 기호 | 의미 | 예 |
|------|------|-----|
| `*` | 아무 문자열 (빈 문자열 포함) | `*.txt`, `hello/*` |
| `?` | 아무 문자 **1개** | `????.txt` → 4글자 이름 |
| `[abc]` | a 또는 b 또는 c | `file[12].txt` |

명령 문자열에 `flag` 가 들어가면 막는 필터가 있을 때:

```bash
# 안 됨
cat ./dream/hack/hello/flag.txt

# 됨 (파일명에 flag 를 직접 안 씀)
cat ./dream/hack/hello/*
cat ./dream/hack/hello/????.txt
```

`*` / `?` 는 **셸이 먼저** 실제 파일 이름으로 펼친 뒤 명령에 넘김.

### 리다이렉트·파이프 (기초)

| 문법 | 의미 |
|------|------|
| `cmd > f` | 출력을 파일로 (덮어쓰기) |
| `cmd >> f` | 이어 쓰기 |
| `cmd < f` | 입력을 파일에서 |
| `cmd1 \| cmd2` | cmd1 출력 → cmd2 입력 |

### 필터

소스에 대략:

```python
if 'flag' in cmd:
    return ... 'No!'
```

명령 문자열에 **`flag` 가 포함되면** 실행 거부.

| 안 됨 | 됨 |
|-------|-----|
| `cat flag.txt` | `cat ./dream/hack/hello/*` |
| `cat ./dream/hack/hello/flag.txt` | `cat ./dream/hack/hello/????.txt` |

### 풀이 순서

1. 서버 생성 → 브라우저 접속  
2. `ls` — 파일 목록 (`hint.txt` 등)  
3. `cat hint.txt` — 경로 힌트 `./dream/hack/hello/`  
4. `ls ./dream/hack/hello/` — `flag.txt` 존재 확인  
5. `cat ./dream/hack/hello/*` — 필터 우회 후 내용 출력  
6. `DH{...}` 제출  

### 치트시트

```text
ls
cat hint.txt
ls ./dream/hack/hello/
cat ./dream/hack/hello/*
```

### 터미널 색으로 숨긴 문자열 (`tail` / drag)

파일을 읽었을 때 이런 식의 안내가 나오는 경우:

```text
Changed to terminal color! Only the tail command can read this string correctly!... or drag? :
```

**의미**

- 플래그(또는 비밀 문자열)가 **터미널 색(ANSI 이스케이프)** 으로 칠해져 있음  
  예: 글자색 = 검정, 배경 = 검정 → `cat` 해도 **안 보이거나** 안내 문구만 보임
- 힌트 두 가지:
  1. **`tail`** 로 읽기 — 문제/환경이 `tail` 을 쓰라고 지정한 경우  
  2. **drag** — 마우스로 출력 영역을 **드래그(드래그 선택)** 하면 선택 하이라이트 때문에 숨은 글자가 보임

**시도할 명령 예**

```bash
# 파일 끝 쪽 보기 (힌트가 tail 을 지목할 때)
tail ./dream/hack/hello/*
tail -n 5 파일

# 색 코드까지 보이게 (이스케이프 문자 표시)
cat -v 파일
# 또는
od -c 파일
xxd 파일 | head
```

| 방법 | 설명 |
|------|------|
| `tail 파일` | 끝부분 출력. 문제가 “tail only” 라고 하면 우선 시도 |
| 드래그 선택 | GUI 터미널/웹 출력에서 빈 것처럼 보이는 줄 드래그 → 숨은 글자 노출 |
| `cat -v` / `od` / `xxd` | 눈에 안 보이는 제어문자·색 코드 확인 |
| 배경색 바꾸기 | 검정 글자가 보이게 테마 변경 (환경에 따라) |

**ANSI 색 (개념)**

- 터미널은 `\033[...m` 같은 **이스케이프 시퀀스**로 글자/배경색을 바꿈  
- 예: 검정 글자 `ESC[30m` … `ESC[0m` (리셋)  
- 일반 `cat` 은 색을 “적용”해서 보여 주므로, 배경과 같으면 안 보임  
- 바이트 그대로 보면 (`cat -v`, hexdump) 코드가 보임  

#837 흐름과 합치면:

```text
ls → cat hint.txt → ls 경로 → cat 경로/*  (또는 tail 경로/*)
# 출력이 이상하면: tail 다시 / 드래그 선택 / cat -v
```

## Linux Lab — ELF / ps / kill

랩 환경: Ubuntu 22.04, 프롬프트 `dreamhack@linux-lab:~$`

### 1. `hello world!` 출력 ELF 만들기

파일 이름 **`hello`**, 형식 **ELF**, 실행 시 출력 문자열이 채점 기준과 **완전 일치**해야 함.

```bash
cat > hello.c << 'EOF'
#include <stdio.h>
int main(void) {
    printf("hello world!\n");
    return 0;
}
EOF

gcc -o hello hello.c
chmod +x hello
./hello
file hello
```

| 포인트 | 내용 |
|--------|------|
| 출력 | `hello world!\n` (대소문자·`!`·개행 정확) |
| 이름 | `hello` (`a.out` 아님) |
| 형식 | `file hello` → **ELF** (셸 스크립트 X) |
| `return 0` | C99+ `main` 에서는 생략해도 0. 필수는 아님 |

```bash
./hello | od -c   # 바이트 확인용
```

### 2. `ps` — 프로세스 목록 / 상태 코드

#### `ps aux`

| 옵션 | 의미 |
|------|------|
| `a` | 다른 사용자 프로세스 포함 |
| `u` | 유저 친화 상세 형식 |
| `x` | 터미널 없는 프로세스도 표시 |

```bash
ps aux | grep ps_test
```

예시 출력:

```text
dreamha+ 30471 ... S+ ... grep --color=auto ps_test
```

→ **`ps_test` 가 아님.** 명령줄에 `ps_test` 문자열이 있어 걸린 **grep 자신**.  
STAT `S+` = sleep + 포그라운드.

`grep` 자기 자신 제외:

```bash
ps aux | grep '[p]s_test'
```

#### `ps -el`

| 옵션 | 의미 |
|------|------|
| `-e` | 모든 프로세스 |
| `-l` | long 형식 (S 열 = 상태) |

```bash
ps -el | grep ps_pid_test
```

실습 출력:

```text
1 R  1001    91     1 26  80   0 -   660 -      ?        00:04:41 ps_pid_test
F S   UID   PID  PPID ...                              CMD
```

| 칸 | 값 | 의미 |
|----|-----|------|
| **S** | **`R`** | Process State Code (**Running**) |
| PID | `91` | 프로세스 ID |
| TTY | `?` | 제어 터미널 없음 |
| CMD | `ps_pid_test` | 프로세스 이름 |

문제 “`ps_pid_test` 의 Process State Code” → 답 **`R`**.

| 코드 | 의미 |
|------|------|
| **R** | Running |
| **S** | Interruptible sleep |
| **D** | Uninterruptible sleep |
| **T** | Stopped |
| **Z** | Zombie |

#### 이름으로 보기

```bash
ps -C ps_test -o pid,stat,cmd
ps -C kill_test_proc -o pid,stat,cmd
```

### 3. `kill` — 프로세스 종료

**PID 숫자**만 인자로 받음. 이름 넣으면 에러.

```text
$ kill kill_test_proc
-bash: kill: kill_test_proc: arguments must be process or job IDs
```

올바른 순서:

```bash
ps -el | grep kill_test_proc
# 4 R  1000   174     1 ... kill_test_proc
#              ^^^ PID

kill 174          # SIGTERM (기본, 정상 종료 요청)
# 안 죽으면
kill -9 174       # SIGKILL 강제
```

실습: `kill_test_proc` PID `174` → `kill 174` 로 종료.

| 명령 | 의미 |
|------|------|
| `kill PID` | SIGTERM (15) |
| `kill -9 PID` | SIGKILL 강제 |
| `killall 이름` | 이름으로 종료 |
| `pkill 이름` | 이름 패턴으로 종료 |

### 랩 세션 요약 (실제 입력 흐름)

```bash
ls
# hello  hello.c  kill_test_proc  kill_test_proc.c

# ELF 다시 만들기
rm hello hello.c   # 필요 시
cat > hello.c << 'EOF'
#include <stdio.h>
int main(void) {
    printf("hello world!\n");
    return 0;
}
EOF
gcc -o hello hello.c

# 상태 코드
ps -el | grep ps_pid_test
# → S 열 R  → 답: R

# kill
ps -el | grep kill_test_proc
# → PID 174
kill 174
```

### 4. 디렉터리 / 숨김 파일 (`pwd`, `ls`, `mkdir`, `rmdir`)

홈 디렉터리 확인:

```bash
pwd
# /home/dreamhack
```

```bash
ls
# flag_90ad6cd7e414a4d2d3e4934b8302052c34ccdb06b2afc4786d3e81202fd51ec9
# remove_dir
```

`ls` 만 하면 **숨김 파일(`.` 으로 시작)** 은 안 보임.

```bash
ls -al
```

| 항목 | 의미 |
|------|------|
| `.` / `..` | 현재 / 상위 디렉터리 |
| `.bashrc` `.profile` 등 | 셸 설정 (숨김) |
| **`.hidden_flag_91a416ea...`** | **숨김 플래그 파일** (`ls` 만으로는 안 보임) |
| `flag_90ad6cd7e414...` | 일반 파일 (긴 해시 이름) |
| `remove_dir` | 비어 있으면 `rmdir` 로 삭제 가능 |

`ls -al` 권한 열 예: `-rw-r--r--`, `drwxr-xr-x`  
- 맨 앞 `-` = 일반 파일, `d` = 디렉터리  

디렉터리 생성 / 빈 디렉터리 삭제:

```bash
mkdir hello_dir      # 폴더 만들기
rmdir remove_dir     # 비어 있는 폴더만 삭제 (안 비어 있으면 실패)
# 내용 있는 폴더는: rm -r 폴더
```

**포인트**

| 명령 | 용도 |
|------|------|
| `pwd` | 지금 경로 |
| `ls` | 목록 (숨김 제외) |
| `ls -a` / `ls -al` | 숨김 포함 / 자세히 |
| `mkdir 이름` | 디렉터리 생성 |
| `rmdir 이름` | **빈** 디렉터리 삭제 |
| `rm 파일` | 파일 삭제 |
| `rm -r 디렉터리` | 디렉터리 전체 삭제 |

랩/CTF에서 “플래그가 안 보인다” → **`ls -al`** 로 `.` 숨김 파일 먼저 확인.

```bash
# 숨김 플래그 읽기 예
cat .hidden_flag_91a416ea73a26a59e80e0a706df9afd2f36371a565f967bff02da9bbb77246c0
# 또는
cat .hidden_flag*
cat flag_*
```

### 개념 1 — 파일 디스크립터 (fd)

프로세스가 파일·터미널·파이프를 열면 커널이 **번호**를 준다.  
프로그램은 그 번호로 읽고 쓴다.

| fd | 이름 | 역할 |
|----|------|------|
| **0** | stdin | 표준 입력 (보통 키보드) |
| **1** | stdout | 표준 출력 (보통 화면) |
| **2** | stderr | 표준 에러 (보통 화면) |
| **3+** | (추가) | `open` 한 파일, 소켓 등 |

**열린 fd 목록 보기**

```bash
ls -l /proc/$$/fd
# $$ = 현재 셸 PID
```

**열린 fd 개수** (랩 문제)

```bash
ls /proc/$$/fd | wc -l
```

| 기호 | 의미 |
|------|------|
| `/proc/PID/fd/` | 그 프로세스가 연 fd 목록 |
| `wc -l` | 줄 수 = 개수 |

나온 **숫자**를 제출. (셸마다 3보다 클 수 있음 — 화면에 나온 값 그대로)

### 개념 2 — 파이프 (`|`)

```text
명령A | 명령B
```

- A의 **stdout** 이 B의 **stdin** 으로 연결됨  
- 화면을 거치지 않고 **프로세스끼리** 데이터 전달  
- 여러 단 가능: `A | B | C`

```bash
# 파일 내용 출력 → 그중 패턴만 고르기
cat pipe_grep_file | grep '패턴'
```

`cat` 만 하면 전체, `grep` 만 쓰면 파일에서 직접 검색도 가능하지만,  
랩은 **`cat` + `|` + `grep` 조합**을 연습시키는 경우가 많음.

### 개념 3 — grep 과 정규식 조각

```bash
grep '패턴' 파일
명령 | grep '패턴'
```

| 패턴 | 의미 |
|------|------|
| `^` | 줄 **시작** |
| `$` | 줄 **끝** |
| `.` | 아무 문자 **1개** |
| `*` | 바로 앞 것을 **0번 이상** 반복 |
| `.*` | 가운데 아무 문자열 (0글자 이상) |
| `-o` | 줄 전체가 아니라 **맞은 부분만** 출력 |

**`.` 이 들어가는 이유**  
`IIIII.*lllll` = `IIIII` + (아무 내용) + `lllll`  
`.*` 가 “사이는 상관없다”는 뜻.  
`*` 만 쓰면 앞 글자 하나에만 걸려서 의미가 달라짐.

### 개념 4 — 리다이렉션

| 문법 | 의미 |
|------|------|
| `명령 > 파일` | stdout을 파일로 (**덮어쓰기**) |
| `명령 >> 파일` | stdout을 파일 끝에 **추가** |
| `명령 < 파일` | 파일 내용을 stdin으로 |
| `명령 2> 파일` | **stderr** 를 파일로 |
| `명령 > 파일 2>&1` | stdout+stderr 둘 다 같은 파일로 |

```bash
echo hello > out.txt      # 화면 대신 out.txt에 저장
echo more >> out.txt      # 이어 쓰기
cat < out.txt             # 파일을 입력으로
ls 없는파일 2> err.txt    # 에러만 err.txt
```

파이프 `|` = 프로세스→프로세스  
리다이렉션 `>` = 프로세스→**파일** (또는 파일→프로세스)

랩에 `redirect_test` 같은 파일이 있으면, 보통  
`명령 > redirect_test` 또는 `cat ... > redirect_test` 형태로 **출력을 파일에 쓰라**는 문제.

### 랩 문제별 해설

#### 문제 — 현재 셸의 열린 fd 개수

**물음:** 지금 셸에 열려 있는 파일 디스크립터 개수

**풀이:**

```bash
ls /proc/$$/fd | wc -l
```

**해설:**  
`/proc/$$/fd` 아래 항목 하나 = 열린 fd 하나.  
개수를 세어 제출. `$$` 는 현재 셸 PID.

---

#### 문제 — pipe + grep + cat 으로 문자열 찾기

**물음:** `pipe_grep_file` 내용 중 **`IIIII` 로 시작**하고 **`lllll` 로 끝나는** 문자열을  
`pipe(|)`, `grep`, `cat` 으로 찾아 제출

**풀이 (권장):**

```bash
# 줄 중간에도 있을 수 있으면 -o 로 부분만
cat pipe_grep_file | grep -o 'IIIII.*lllll'

# 줄 전체가 정확히 그 형태일 때
cat pipe_grep_file | grep '^IIIII.*lllll$'
```

**해설:**

1. `cat pipe_grep_file` — 파일 전체를 stdout으로  
2. `|` — 그 출력을 grep 입력으로  
3. `grep 'IIIII.*lllll'` — 시작·끝 패턴에 맞는 줄/부분  

| 안 나올 때 | 조치 |
|------------|------|
| `^` `$` 때문에 실패 | 줄 앞뒤에 다른 글자 → **`grep -o`** 사용 |
| `\r` (CRLF) | `tr -d '\r' \| grep -o 'IIIII.*lllll'` |
| 아무것도 없음 | `grep IIIII pipe_grep_file` 로 파일 내용 확인 |

**`.*` 의미 복습:** `.` = 아무 문자 1개, `*` = 0회 이상 → 사이 통째로 매칭.

---

#### 문제 — 리다이렉션 (환경에 `redirect_test` 있을 때)

홈에 `redirect_test` 가 보이면 리다이렉션 연습용.

```bash
ls
# pipe_grep_file  redirect_test

# 예: 출력을 파일로
echo '내용' > redirect_test
# 또는 문제에서 시킨 명령을 redirect_test 로
명령 > redirect_test
cat redirect_test   # 확인
```

**해설:**  
`>` 가 stdout(fd 1)을 화면 대신 파일에 연결한다.  
이후 `cat redirect_test` 로 잘 들어갔는지 확인.

### 치트시트

```bash
# fd 개수
ls /proc/$$/fd | wc -l
ls -l /proc/$$/fd

# pipe + grep
cat 파일 | grep '패턴'
cat 파일 | grep -o 'IIIII.*lllll'

# 리다이렉션
명령 > 파일
명령 >> 파일
명령 2> 에러파일
명령 < 입력파일
```

### 한 줄로 다시 보기

1. **fd** = 열린 입출력에 붙인 번호 (0·1·2 기본)  
2. **`|`** = 출력을 다음 명령 입력으로  
3. **`>`** = 출력을 파일로  
4. **grep** = 패턴 필터 (`.*` = 가운데 아무 문자열)  
5. 랩: fd 개수 세기 + `cat \| grep` 으로 문자열 찾기 + 리다이렉션

## 오늘 배운 것 (한 줄)

1. `ls` / `cd` / `cat` / `pwd` 로 탐색·읽기
2. `head` = 앞, **`tail` = 뒤**
3. `gcc -o hello hello.c` 로 ELF 생성, 출력·파일명 정확해야 채점 통과
4. `return 0` 은 `main` 에서 필수는 아님 (C99+)
5. `ps aux` / `ps -el` 로 목록·**STAT/S** 상태 코드 확인
6. `ps ... \| grep foo` 에 뜨는 `grep foo` 줄은 대상 프로세스가 아님
7. `kill` 은 **PID**, 이름이면 `killall` / `pkill`
8. 문자열 필터(`flag`)는 `*` / `?` 글로브로 우회
9. 터미널 색으로 숨긴 문자열 → `tail` / 드래그 / `cat -v`
10. `ls` 는 숨김 안 보임 → **`ls -al`**
11. `mkdir` / **`rmdir`**(빈 폴더) / `rm -r`
12. **fd** = 입출력 번호; `/proc/$$/fd` 로 개수·목록
13. **pipe** `\|` = 명령 연결; **grep** 으로 필터; `.*` = 사이 아무 문자열
14. **리다이렉션** `>` `>>` `<` = 파일로 입출력 돌리기
