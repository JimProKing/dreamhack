## 2. 웹 해킹을 위한 웹 기초 지식

### 핵심 개념 요약

#### 웹 · HTTP

- 클라이언트(브라우저) ↔ 서버, 약속은 **HTTP/HTTPS**
- 한 번의 통신 = **요청 + 응답**
- HTTP 는 **무상태** → 로그인 등은 쿠키·세션으로 별도 유지 (다음 유닛)
- 요청: 시작줄(메서드·경로) + 헤더 + (바디)  
- 응답: 상태 코드 + 헤더 + 바디

| 자주 쓰는 코드 | 의미 |
|----------------|------|
| 200 | 성공 |
| 302 | 리다이렉트 |
| 401 / 403 | 인증 / 권한 |
| 404 | 없음 |
| 500 | 서버 오류 |

| 메서드 | 관례 |
|--------|------|
| GET | 조회 (쿼리) |
| POST | 제출 (바디) |

**HTTPS** = HTTP + TLS. 전송 구간 보호. 앱 버그(권한 검사 누락 등)는 별개.

#### 브라우저 · URL · DNS

```text
스킴://호스트:포트/경로?쿼리#프래그먼트
```

- DNS: 도메인 → IP  
- `#fragment` 는 서버로 안 감 (클라이언트만)

#### DevTools (웹 문제의 기본 도구)

| 패널 | 볼 것 |
|------|-------|
| Network | 실제 요청·응답·헤더·쿠키 |
| Application | Cookies, Storage |
| Sources | JS/숨은 파일·주석 |
| Console | JS 실행, `document.cookie` 등 |
| Elements | DOM 구조 |

관찰 순서 습관:

```text
Network → Application(Cookies) → Sources → Console
```

**devtools-sources** 유형: Sources 트리에서 숨겨진 리소스·코드를 찾는 연습.

상세: [01-web-http-https](../web_basics/01-web-http-https.md), [02-browser-devtools](../web_basics/02-browser-devtools.md)

## 3. Cookie & Session

유닛: https://dreamhack.io/lecture/units/webhacking-cookie-session  
상세 노트: [`web_basics/03`](../web_basics/03-cookie-session.md), [`04`](../web_basics/04-sop-cors.md)

### 구성 (유닛 목차)

| 블록 | 내용 |
|------|------|
| Cookie & Session | 배경, Lab, Quiz, Exercise: cookie / session-basic |
| Same-Origin Policy | SOP 완화·정책, Lab, Quiz |

### Cookie vs Session

| | Cookie | Session (일반 패턴) |
|--|--------|---------------------|
| 데이터 위치 | 브라우저 | 서버 |
| 클라이언트가 갖는 것 | 이름=값 자체 또는 세션 ID | 보통 **세션 ID 쿠키만** |
| 매 요청 | `Cookie` 헤더로 자동 전송 | 서버가 ID 로 상태 조회 |
| 변조 | 값을 직접 고치기 쉬움 | ID 탈취·추측이 이슈 |

HTTP 가 상태를 안 기억하므로,  
**쿠키로 “이 요청이 누구 것인지” 를 실어 보낸다.**

### 쿠키 보안 속성

| 속성 | 역할 |
|------|------|
| HttpOnly | JS 로 읽기 불가 (XSS 완화) |
| Secure | HTTPS 만 |
| SameSite | 크로스 사이트 전송 제한 (CSRF 완화) |
| Domain / Path | 어디에 붙는지 |
| Max-Age / Expires | 수명 |

### 분석 시 질문

1. 쿠키 값에 **역할·권한이 평문으로** 들어 있는가? → 변조 실험  
2. 세션 ID 는 **추측 가능한가?** 로그인 전후 ID 가 바뀌는가?  
3. 서버가 권한을 **다시 검증** 하는가, 쿠키만 믿는가?

| 연습 | 방향 |
|------|------|
| cookie | 쿠키 기반 인증 → Application 에서 값 확인·변조 |
| session-basic | 세션 저장 + 쿠키 ID → admin 조건·세션 내용 추적 |

### SOP · CORS (같은 유닛)

**Origin** = 스킴 + 호스트 + 포트

- **SOP**: 다른 origin 스크립트가 이 origin 데이터를 함부로 **못 읽게**  
- **CORS**: 서버가 응답 헤더로 “이 origin 은 읽어도 됨” 을 **명시적으로** 허용  

| 헷갈리기 쉬운 점 | 정리 |
|------------------|------|
| 다른 사이트에서 내 사이트로 요청 | 갈 수 있음 (쿠키 조건에 따라) → CSRF 맥락 |
| 그 응답을 JS 로 읽기 | SOP/CORS 가 막거나 허용 |
| 쿠키 자동 첨부 | SameSite · Secure · 도메인 규칙 |

상세: [03-cookie-session](../web_basics/03-cookie-session.md), [04-sop-cors](../web_basics/04-sop-cors.md)
